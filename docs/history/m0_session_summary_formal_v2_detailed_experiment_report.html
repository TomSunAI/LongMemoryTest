4.1 与完整 LD-Agent event memory 的差异

  • M0 保留 ld_agent_metadata.memory_name = event_memory 的兼容字段，但实际 memory unit 是 completed session/day 的 summary。
  • 不做 event detection、event identity resolution、event merge、persistent event update、event trajectory construction。
  • 不把 relational anchors、shared handling strategy、boundary-sensitive cues 写成长期策略记忆。
  • Probe turn 是 read-only：读取记忆生成回答，但默认 skip_probe_writeback，避免评估问题污染长期记忆。

4.2 Prompt 压缩

当前代码策略topics 不再写入 LLM prompt。prompt 只保留 session summary 内容、source_session、score、overlap、time_decay。
保留策略完整 topics 仍保留在 retrieval JSON diagnostics 和 memory snapshot，用于检索、审计和复盘。
v2 正式实验历史行为本报告对应的 v2 正式实验产物是在修正前生成的，当时 prompt 中仍有压缩后的 topics=...(+N)。该行为已在当前代码中移除。

4.3 Topic 到底渲染什么

这里的 topics 不是自然语言摘要，也不是最终回答内容，而是每条 session_summary_memory 附带的检索标签。它由 domain、脚本 topic、用户输入/summary/raw dialogue 中抽出的中文和英文关键词/ngram 混合组成，用于 topic overlap 检索与诊断。

完整保存位置responses_by_condition.json 的 memory_context.retrieval.session_hits[].memory.topics / memory.topic。这里保留完整 topic 列表，通常可达到数百到两千多个条目。
当前是否给 LLM 看不看。当前代码已移除 topics=... prompt 渲染；topics 只参与检索和 diagnostics。
当前 prompt metadata 行source_session=...; score=...; overlap=...; time_decay=...
不会渲染 topic 的地方Current short-term session 只渲染当前 session 的 User/Agent 文本；Persona memories 只渲染 persona summary，不渲染 persona topic metadata。

5. 正式执行流程

每个 turn 的执行路径保持一致，只改变 M0 的长期记忆状态。整体流程如下：

  1. 从脚本输入中取出当前 message_id、day、topic、domains、turn_type。
  2. M0 runtime 根据当前 user input、topic、domain 和短期 session 内容做 topic_overlap_time_decay 检索。
  3. 构造 memory_context：包含 session summary hits、persona hits、short-term session 摘要信息和 source_detail_ids。
  4. 调用主 LLM 生成 M0 assistant answer。
  5. 按 turn type 写回：ordinary opening/followup 进入 short-term session；probe read-only；跨 session 时将上一 session flush 成 session summary。
  6. 写入 responses_by_condition.json、conversation_log.json，并在最终 snapshot 中保存 M0 memory bank。
  7. 运行 scripts/06_evaluate_tom.py 对 36 条 targeted_probe 做 rule-based ToM triage。

9. ToM 评估方法

12. 结果解释

12.1 当前 M0 的优势

  • 正式 v2 能稳定跑完全量 96 turns，说明 prompt compaction 后 M0 baseline 可作为后续 M1-M3 对照的底座。
  • session summary + persona retrieval 在中后期大多数 turn 都能提供 top-k 上下文：77/96 turns 命中 5 条 session summary，81/96 turns 命中 5 条 persona。
  • alienation/ask-repeat/generic-comfort 三类显式风险在 rule-based triage 中均为 0，说明没有明显“疏离式追问”或空泛安慰倾向。

12.2 当前 M0 的短板

  • natural_detail_use 平均 raw score 只有 0.29/2，是最弱维度；说明 M0 能调用关系/意图框架，但自然嵌入具体细节的能力不足。
  • 低分集中在 natural_detail 和 relational_boundary probe，尤其 D06_P002、D20_P001，显示 M0 有时会过短、截断或没有充分贴合 probe 要求。
  • Persona writer 有 19 次 fallback，SessionSummary writer 有 7 次 fallback；虽然没有中断正式实验，但说明 memory writer LLM 的空返回仍是工程风险。
  • 由于 M0 不做 event identity/trajectory，长期跨事件演进只能通过 session summary 的文本相似度间接体现，不能代表完整 LD-Agent event memory 能力。

12.3 后续对照实验建议

  • 以本次 v2 为 M0 baseline，后续 M1/M2/M3 对照应保持同一输入、模型、temperature/top_p/max_tokens 和 serial/parallel 口径。
  • 补充 LLM-as-judge 或人工 blind review，用于验证 rule-based ToM triage 对“自然细节使用”和“关系边界”的判断。
  • 单独跟踪 writer fallback，必要时提高 memory writer token limit、改 JSON schema 或加更严格 retry parse，以降低 deterministic fallback 比例。
