M0-M3 记忆系统技术方案与执行细节

版本：2026-06-07 · 项目：LongMemoryTest · 路线：LD-Agent-compatible M0 + Relational Memory Overlay

核心原则： M0 是 M1/M2/M3 的唯一共同基石。M1/M2/M3 不允许重新实现一套 generic memory search，也不允许绕开 M0 的 storage backend / retrieval strategy；它们只能在同一份 M0 search/indexing 输出上叠加关系型记忆层。

1. 总体结构

用户输入
  ↓
M0 LD-Agent-compatible generic memory search/indexing
  ↓
M0 payload: short-term session + event memory + persona traits + retrieval metadata
  ↓
M1 = M0 search output + conclusion-level relational overlay
M2 = M0 search output + M1 + summary-level relational event overlay
M3 = M0 search output + M1 + M2 + detail-level relational anchor overlay
条件 定义 能读取 不能读取
M0 LD-Agent-compatible memory-only generic baseline 同 session user turns、普通 event memory、普通 persona traits、M0 retrieval metadata 关系型记忆、BEI、gold strategy、probe type、failure mode、人工事件阶段、M2/M3 锚点
M1 M0 + 结论级关系记忆 M0 完整 search 输出、稳定偏好、回应风格、关系期待、回应边界 具体事件线、日期、原话、细节锚点、人工评测信息
M2 M0 + M1 + 摘要级关系事件记忆 M0 完整 search 输出、M1、跨天主题进展、状态变化、事件摘要 原始全文、未筛选细节、完整历史片段、人工评测信息
M3 M0 + M1 + M2 + 细节级关系锚点 M0 完整 search 输出、M1、M2、必要细节、共同语言、调用边界、误用风险 未存事实、无关隐私细节、完整原始历史、人工评测信息

2. M0：LD-Agent-compatible Memory Baseline

M0 使用本项目的 LDAgentMemoryRuntime 实现。它参考 LD-Agent 的 Module/EventMemory.py 和 Module/Personas.py，只复现记忆侧机制，不使用 LD-Agent 的 response generator、ChatGLM3、LoRA checkpoint 或训练脚本。

2.1 M0 写入流程

  1. 每轮回答完成后，M0 把当前 user turn 追加到 short_term_session。
  2. 同一轮后，按 Personas-style prompt 从 user inquiry 和 M0 response 中抽取 user/agent traits。
  3. 当 day/session boundary 发生时，把上一 session 拼成 (line n) User: ... 格式。
  4. 使用当前实验 LLM 做 session summary，写入 generic event memory。
  5. event memory 保存 LD 风格 metadata：idx、dialog、time、topics、datatype、summary。

2.2 M0 searching / indexing

默认 JSON backend

event memory 写入 JSON snapshot；检索时直接遍历 snapshot 里的 event memory。

query topics
  × memory topics overlap
  × time decay
  → sorted top-k

可选 ChromaDB backend

event memory summary 写入 ChromaDB；检索时先由 ChromaDB 返回候选 memory ids，再用 LD-style 规则重排。

Chroma candidate ids
  → topic-overlap + time-decay rerank
  → sorted top-k

最终排序公式：

score = topic_overlap_score * exp(-decay_temp * time_gap)

spaCy 当前不接入。原因是 LD 原版 spaCy en_core_web_sm 主要服务英文 noun lemma extraction，而本实验是中文长期对话；当前使用可审计中文 topic tokenization，结合 message.topic、domains 和 user text 构建 topics。

3. M1/M2/M3：基于 M0 的关系型 Overlay

M1/M2/M3 的输入 payload 由 _with_m0_base_memory 构造。该函数先要求 M0 payload 非空，再把关系型 payload 作为 overlay 追加。这样日志中能明确看到：关系层不是独立搜索系统，而是基于 M0 search output 的增量层。

3.1 组合字段

{
  "memory_composition": {
    "base_condition": "M0",
    "base_provider": "ld_agent_memory",
    "base_payload_required": true,
    "base_payload_shared_by": ["M1", "M2", "M3"],
    "overlay_condition": "M1 | M2 | M3",
    "overlay_source": "memory_conditions",
    "composition_rule": "M0_search_output_plus_relational_overlay"
  },
  "search_indexing_policy": {
    "uses_m0_search_indexing": true,
    "m0_retrieval_strategy": "ld_agent_relevance_overlap_time_decay",
    "m0_storage_backend": "json | chroma",
    "relational_layer_has_independent_generic_search": false,
    "relational_layer_role": "overlay_after_m0_search"
  }
}

3.2 上下文拼接顺序

M0 基石记忆检索结果
  ↓
M0 memory_context
  ↓
M1/M2/M3 关系型增量记忆层
  ↓
共同使用边界：先使用 M0 generic search，关系层只能 overlay
字段 作用
m0_base_memory 保存 M0 的 provider、source ids、retrieval、memory_context，供审计 M1/M2/M3 是否共享同一 M0 search output。
relational_overlay 保存当前条件自己的关系型增量记忆，不允许替换 M0 base memory。
retrieval.strategy 对 M1/M2/M3 固定为 m0_base_search_plus_relational_overlay。

4. 执行链路

  1. 读取 daily messages、scene cards、probe plan 和 memory conditions。
  2. 初始化 M0 runtime。若 resume 且存在 m0_ld_agent_memory，优先从 snapshot 恢复。
  3. 每个 user turn 到来前，M0 执行 search/indexing，生成 M0 payload。
  4. 同一个 M0 payload 被传入 M1/M2/M3 的 overlay 构造逻辑。
  5. 同一条 user message 同时喂给 M0/M1/M2/M3，模型和短期上下文策略保持一致。
  6. 四条件回答完成后，只用 M0 回答写回 M0 memory runtime，避免条件互相污染。
  7. checkpoint 写出 responses、conversation log、run_config 和 M0 snapshot。

7. 论文引用与边界

LD-Agent 可作为 M0 generic memory baseline 的来源引用，但表述必须准确：

  • 推荐：LD-Agent-compatible memory-only baseline
  • 推荐：LD-Agent-inspired memory reproduction for generic long-term dialogue memory
  • 避免：声称完整使用 LD-Agent agent 或原版 response generator。
